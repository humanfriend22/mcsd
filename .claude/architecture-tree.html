MCSD — Code Interaction Tree

Go daemon (core + api + cli) + Vue/Nuxt frontend. Generated overview of how pieces call each other.
browser → web/services/api.ts (fetch) → api/*.go (HTTP) → core/*.go (logic) → systemd D-Bus / filesystem
terminal → cli/*.go → core/*.go → systemd D-Bus / filesystem  (bypasses api/web entirely)

Entry point

main.go
 └─ cli.Execute()
     ├─ core.InitSDManager()  (D-Bus, boot)
     ├─ cli/*.go (create, edit, instance, upgrade, console, daemon, init, deinit, systemd)
     │    └─ core/*  (all instance ops — same core CLI+API both use)
     └─ daemon.go → api.Serve(8080)
          └─ src/web/web.go (embed+serve Nuxt SPA build)

api/ — HTTP layer

 ├─ api.go       — router, error→status mapping
 ├─ instances.go — CRUD + start/stop/enable/disable
 ├─ files.go     — file browser endpoints
 ├─ logs.go      — chunked log stream
 ├─ rcon.go      — RCON exec endpoint
 ├─ vitals.go / snapshot.go — host resource metrics
 ├─ cache.go     — bg goroutine, refresh instance list every 2-5s
 └─ init.go / ready.go — bootstrap/health
        all → core/*  (no cross-talk to cli/)

core/ — shared brain (cli + api both depend on this, nothing depends back)

 ├─ core.go            — init/deinit host, global config
 ├─ instance.go        — lifecycle: launch/stop/download/upgrade
 ├─ instance_model.go  — merges config+ports+systemd state → Instance struct
 ├─ instance_config.go — persist config.json per instance
 ├─ ports.go           — server.properties parse/validate
 ├─ systemd.go         — D-Bus: SDManager singleton, unit control+status
 ├─ rcon.go            — Minecraft RCON protocol
 ├─ java.go            — java binary discovery
 ├─ memory.go          — mem budget calc
 ├─ vitals.go          — CPU/RAM/disk read
 └─ config.go          — global config.json
        └─ vendors/ (fabric.go, paper.go via vendors.go registry+interface)
        └─ utils/errors.go (ValidationError / NotFoundError / ServerError)

web/ — Vue/Nuxt SPA (talks only to api/ over HTTP)

 pages/
  ├─ index.vue            → ServerCard.vue list
  └─ instances/[id].vue   → InstanceHeader, tabs (Overview/Settings), LogViewer, FileBrowser
 components/ → StatusDot, InstanceStatCard used inside tabs
 services/api.ts   — fetch wrapper, all HTTP calls
 services/error.ts — error normalize
 utils/format.ts, merge.ts — helpers
Enforced rule: cli/ and api/ both depend on core/, never on each other. Keeps the CLI a fully standalone, reliable alternative to the web UI.
